01 · Findings

1. Access is the product-ops choke point

Many platforms expose broad REST/GraphQL APIs, but agent distribution introduces app review, partner approval, admin-only credentials, production onboarding or paid API gates.

Implication: model credential acquisition as a state machine, not just “add an Authorization header.”

2. OAuth + machine tokens form the core architecture

OAuth2 is the recurring multi-user pattern; API keys/tokens dominate internal or single-account automation. Mature connectors often expose both.

Implication: build reusable auth adapters and explicit scope/approval states.

06 · Easy wins vs outreach

Easy-win candidates

Self-serve, broad APIs are the natural first engineering queue: GitHub, Slack, Notion, Linear, Asana, ClickUp, monday.com, Netlify, Vercel, Sentry, SendGrid, Mailchimp, Firecrawl and similar platforms.

Outreach candidates

Technically useful but access-gated systems should enter an outreach queue: Aircall OAuth, Copper OAuth, Google Ads developer-token/access levels, LinkedIn/Meta review, Amazon SP-API authorization, Plaid production access and enterprise research/data APIs.

07 · Limitations

“Conditional” and “not found” are intentionally conservative. “Not found in docs-first scan” does not prove that no community MCP exists. API plans, app-review policies and MCP offerings can change; rerun and re-verify before production use.
